# paperengine

Tooling for writing one conference paper that a committee will believe.

The engine does not write the paper. It removes the failure modes that make
machine-assisted papers fail: citations that do not exist, numbers that cannot
be traced, prose nobody took responsibility for, and formatting that triggers a
desk rejection before a reviewer reads a word.

Target venue: **ICLR 2027** — abstract due 2026-09-18 AOE, full paper due
2026-09-25 AOE, decisions 2026-12-16, conference 2027-04-26 to 04-30 in
San Francisco.

## Why these gates and not others

The gates are not chosen by taste. They come from what ICLR reviewers actually
complain about. Across 1,542 annotated ICLR reviews from the ASAP-Review corpus,
counting how often each aspect is raised as a criticism versus as praise:

| Aspect | Share of mentions that are criticism |
| --- | --- |
| Replicability | 94.1% |
| Meaningful comparison to prior work | 90.4% |
| Substance of the experiments | 73.8% |
| Clarity | 62.0% |
| Soundness | 61.4% |
| Originality | 51.0% |
| Motivation | 27.1% |

Novelty is raised as often in praise as in criticism. Reproducibility and
missing comparisons are raised almost only in criticism. A paper is far more
likely to die from a baseline it did not run than from an idea that was not new
enough.

The corpus covers ICLR 2017–2020 and so predates the current review climate;
treat the ordering as a strong prior, not a measurement of 2026. The counts are
regenerated by `results/iclr_rejection_aspects-*.json`.

## Gates

    python -m paperengine.cli check --dir paper/submission

1. **Build.** `latexmk` against the official, unmodified ICLR 2027 style files.
2. **Citations** (`refcheck`). Every `.bib` entry must resolve against arXiv,
   OpenAlex, Crossref or Semantic Scholar, and the returned title must match.
   An entry with a DOI or arXiv id is checked against it; an entry without one
   must survive a title search at 0.88 similarity. A rate-limited API yields
   `UNAVAILABLE`, never `NOT_FOUND` — mistaking a network failure for a
   fabricated citation is the one error that would make the gate useless.
3. **Numbers** (`provenance`). Empirical numbers are `\newcommand` macros
   generated from recorded runs, so a stale number is a compile error rather
   than a silent lie. The audit flags any numeric literal typed into the
   LaTeX by hand.
4. **Prose** (`style`). Vocabulary and phrasing whose frequency rose sharply in
   the literature after 2022, plus a sentence-rhythm measure. Advisory: it
   points, a person decides.
5. **Submission rules** (`compliance`). Nine-page main text measured from
   `\label{lastmainpage}`; anonymity, including PDF metadata and repository
   URLs; the mandatory AI use statement; style-file integrity by hash; margin
   and spacing manipulation; leftover placeholders.

## Supporting modules

- `litreview` — builds a literature corpus by seeding queries then snowballing
  forward and backward through the OpenAlex citation graph, emits verified
  BibTeX, and reports a coverage figure so that an absence in the corpus can be
  weighed rather than trusted. `verify_gap` re-checks a claimed gap with direct
  phrase queries.
- `stats` — paired permutation tests, bootstrap intervals, Holm and
  Benjamini-Hochberg, Wilson intervals, minimum detectable effect,
  Diebold-Mariano, Cohen's kappa and Krippendorff's alpha. Plus the corrections
  quantitative finance built for selection bias and machine learning has mostly
  not imported: `deflated_score` and `probability_of_selection_overfit`.
- `figures` — Okabe-Ito palette reordered for maximum separation under
  deuteranopia (validated: worst adjacent ΔE 9.6), colour never the only
  encoding, one y-axis enforced, provenance sidecar written beside every figure.
- `review` — four reviewer personas, an objection tracker that only counts an
  objection as resolved when a later round stops raising it, and a readiness
  test that weights the lowest score above the mean.

## Disclosure

ICLR 2027 requires an AI use statement, so there is nothing to conceal and no
reason to try. The engine's purpose is that the work behind the disclosure is
sound: real citations, traceable numbers, reproducible experiments. `style` is
about prose quality, not camouflage.

## Layout

    paperengine/     the engine
    paper/_official/ pristine ICLR 2027 style files, for hash comparison
    paper/submission/ the paper being written
    results/         one JSON per recorded run
    out/             gate reports
    tests/

## The study

`study/` is the paper. Everything below regenerates from two extraction files
and one command.

    ./run_all.sh

That runs, in order: every analysis (`make_all.py`), the two that need no error
bars (`binomial_check.py`, `benchmark_resolution.py`), the benchmark reference
table (`resolution_table.py`), the LaTeX macros (`make_numbers.py`), the
figures, a clean LaTeX build, and the five submission gates. It touches no
network and is deterministic: the bootstrap is seeded. A rerun reproduces every
artifact byte for byte, which was tested rather than assumed.

Building the corpus itself is the one step that does touch the network:

    python study/pipeline.py --source neurips2025 --source icml2025 \
        --sample 2000 --seed 0 --out data/extracted_2025.jsonl
    python study/pipeline.py --source neurips2024 --source icml2024 \
        --sample 1200 --seed 0 --out data/extracted_2024.jsonl

It downloads each PDF from the open proceedings, extracts it, records its
SHA-256, and discards it. The JSONL is the checkpoint, so an interrupted run
resumes. Sources are `neurips2024`, `neurips2025`, `icml2024`, `icml2025`.

### What each file does

| file | role |
| --- | --- |
| `harvest.py` | index the open proceedings; download with a cached, hashed manifest |
| `pipeline.py` | download, extract, discard, at corpus scale, with per-host concurrency limits |
| `extract.py` | the instrument: tables from captions, lines from vertical overlap, bold from font flags, the NeurIPS checklist answer |
| `analyze.py` | comparisons from tables, orientation and direction from typography, the z test, Holm within table, the cluster bootstrap |
| `sensitivity.py` | both readings of every convention the pipeline had to choose; power audit; correlation range |
| `binomial_check.py` | checkability without error bars: how large a test set the reported gaps would need |
| `benchmark_resolution.py` | the same, against the benchmark a caption actually names |
| `resolution_table.py` | what each benchmark in common use can resolve, from its published split |
| `extra_stats.py` | the numbers that answer reviewer objections, computed rather than typed |
| `crosscheck.py` | a second extractor on different principles, for an agreement rate |
| `contact_sheet.py`, `validate.py` | render sampled tables so a person can look at them |
| `make_numbers.py` | every number the paper prints, as a macro traced to a run |
| `make_all.py` | one entry point for all of the above |

### Hand-judged inputs

Three things a script cannot regenerate, because a reader supplied them.

- The **gold set** (`study/gold_set.py`). `sample` draws claims and tables in
  four strata, renders each from the PDF with the pipeline's chosen cell
  circled and nothing else, and writes an answer sheet; the reader fills the
  sheet blind to the pipeline's values (`out/gold/labels.csv`), and `score`
  compares field by field with Wilson intervals and recomputes the failure
  rate from the reader's values. `score --rescore-with` scores a later
  pipeline on the same claims; `sample --exclude-items` draws a held-out set
  from papers the first never touched. The first hundred items found five
  extractor bugs; the held-out set is the number the paper stands on.
- The **recall audit**: tables the extractor called empty, rendered six to a
  sheet (`study/contact_sheet.py`) and judged for whether any error bar is
  present. `out/gold_recall/manifest.json`.
- The **rejected-table audit**: twelve tables discarded for lacking a
  single-bold group, classified by eye. `out/rejected/manifest.json`.

The rendered images are alongside the verdicts in every case, so the
judgements can be repeated by someone who has not seen the pipeline's output.
They are the only typed numbers in `make_numbers.py`, and they say so.

### Every bug has a test

Fourteen extractor bugs are recorded in the commit history and in Appendix E of
the paper with what each did to the numbers. All were found by rendering a
sampled table and looking; none by reading code. Each has a regression test in
`tests/test_extract.py` that reproduces the table pattern on synthetic spans:

    python -m pytest tests
